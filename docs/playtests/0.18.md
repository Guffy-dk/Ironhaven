# Ironhaven 0.18 playtest

18 November 2026. This is a repeatable simulation playtest and a separate GPU rendering regression, not a manual Windows playthrough. Native Windows startup, controls and screenshots are checked by the Windows build.

## Campaigns

The scripted player builds real iron, copper, steel, circuit, gear and component production, routes physical goods through conveyors and numbered hubs, supplies ammunition, manages sawmill production, repairs damage and rebuilds losses. It uses normal commands and earned resources. It does not inject stock, levels, health or kills, and waits through normal preparation intervals. Each run starts from a normal coastal expedition with the starter inventory.

The supplied defense uses four sentries, twelve gun emplacements and four mortars when fully built. The single-weapon policy uses one gun turret with the same production and upgrade rules. The single-weapon run loses at swarm 7. The supplied defense wins two of three seeds, with the third loss at swarm 24. The two completed campaigns defeat all 2,675 enemies across 25 swarms. Wins still require hundreds of repairs and rebuilding actions; this bot reacts every two simulated seconds. Human difficulty needs tester feedback.

At swarm 9, the industrial runs hold 314, 208, 201 plates, respectively. Their maximum combined stock across all resource types is 1618, 1622, 1626. Those numbers are outcomes of this particular production plan, not universal resource ceilings.

## Damage and progression

Drills and smelters add 25% of base speed per purchased upgrade. Refined plates stay one-to-one with ore; the previous speed-and-yield multiplication is removed. Ordinary industrial speed upgrades add 10%. Late industrial levels require components, and turret levels 16–30 also require components. All four turret types stop at level 30; high levels unlock across the campaign.

Armor and armored mutations add further resistance. At level 30 a gun deals 115 direct damage; an ordinary final-swarm runner has 398 HP. A mortar deals 184 direct damage and reduced splash damage. A single upgrade stack cannot one-shot every late creature.

## Rendering and controls

The regression renders 80 creatures at zoom 14 and 44, then 160 creatures at zoom 14. All three full-resolution floating-point framebuffer reads contain zero non-finite values. Before the fix, the same zoomed-out case reproduced black rectangles; three invalid creature-shading channels were spread by bloom. Creature shading now rejects invalid output before postprocessing.

Lamp light slots remain constant at eight; warmed GPU pipelines and halo geometry reuse 36 shader programs before and after placement. On this machine, measured complete synchronized frames were 0 lamps: 13 ms; 1 lamps: 20 ms; 2 lamps: 26 ms; 8 lamps: 38 ms. The initial GPU work occurs behind the loading screen. A link-only warmup still stalled for 2,960 ms, so program-count checks alone were insufficient. These SwiftShader timings are a local regression comparison, not a hardware FPS claim.

Automated interface/simulation checks cover mixed shared storage limits, physical warehouse outputs, surplus-save migration, proportional turret-health migration, Q single and group dismantling, combat protection, numbered hub programming, fractional conveyor timing, paused production and level caps. All twenty belt upgrades shorten actual transport over a twenty-tile route; leftover time carries into the next tile.

## Reproduce

- `npm test`
- `npm run test:campaign -- 417 industry` (also seeds 2026 and 7)
- `npm run test:campaign -- 417 single`
- `CHROME_BIN=/usr/bin/chromium npm run test:render` (or install the Playwright Chromium runtime and omit CHROME_BIN)
- Windows: `./scripts/build-windows.ps1`
