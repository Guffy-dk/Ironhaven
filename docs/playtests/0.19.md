# Ironhaven 0.19 playtest and optimization

18 November 2026. Campaign results come from a deterministic player using the authoritative simulation and ordinary player commands. They are not manual Windows playthroughs. Rendering and performance measurements below use local Node and headless Chromium with SwiftShader. Native Windows startup, controls, screenshots and published patcher installation have separate build checks.

## Rendering and simulation

The baseline is tag `v0.18.0`. Both rendering versions use 1280×800, standard shadows and bloom. Ten synchronized frames follow three warm frames per scenario. A one-pixel readback drains the GPU queue after every measured frame. Calling only `gl.finish()` returned before deferred rasterization completed in this Chromium setup and gave misleading submission-time measurements; those preliminary timings are discarded. The large rendering fixture has 432 structures and 420 enemies; the CPU fixture has 700 structures and 420 persistent enemies over 500 measured ticks. These are synthetic load fixtures, not earned campaign positions.

The lower triangle count comes from reusing the static shadow map at distance. Mesh packing preserves every vertex position, UV and triangle index. Normals use normalized signed 16-bit integers, colors normalized 8-bit integers, and indices use 16 bits where possible. No authored geometry is simplified by packing. Existing distance meshes remain in use.

Workshop instances share geometry and materials within 24-tile chunks. Individual buildings retain their original meshes for inspection occlusion, their level plates and selection behavior. Moving, replacing or dismantling buildings rebuilds the grouping. Dynamic parts remain individual meshes. Transparent outlines explicitly apply instance transforms.

Close Shell Guard and Abyss Walker captures differ from the baseline by at most one RGB value out of 255, with mean absolute differences 0.0021 and 0.0015. In the wide scenes, fewer than 0.55% of pixels differ by over ten values, chiefly where the articulated distance shadows become contact shadows. Both close views retain animated shadows.

The complete final CPU fixture state hashes match:
`539e6f3f45e1d067d8a112d01a860b44e2f4775df8fd2486f4f113ba0fb7d50d`.
Transient WeakMap indexes are not saved or replicated. Ordinary build/move/removal and save loading invalidate indexes; targeting ties preserve original building order.

Completed-frame local renderer medians were 3042.8 → 2110.3 ms in the wide scene and 6920.0 → 5065.8 ms in the large factory fixture (approximately 31% and 27% less time). Close Shell Guard and Abyss Walker views were essentially unchanged at 1707.6 → 1705.6 ms and 1572.5 → 1537.8 ms. These high absolute times reflect CPU software rasterization of a detailed scene. The earlier 19.5/28.7 ms submission figures did not wait for rasterization and must not be interpreted as frame rates.

These software-renderer timings are not hardware FPS promises. Geometry bytes, draw calls, raster comparisons and deterministic state equality provide the more portable evidence.

## Campaigns and combat

The test player builds and supplies real production, manages shared storage, exports physical warehouse goods, reserves ammunition, repairs damage and rebuilds losses every two simulated seconds. After two minutes without a kill it stops continually repairing or replacing uncovered structures near the surviving raiders, instead of prolonging an uncovered outpost fight indefinitely. It waits through normal preparation intervals. No resources, health, kills or levels are injected. Three established seeds cover all three difficulties, with an additional standard holdout seed and alternative defense compositions. Full results are in [0.19-results.json](0.19-results.json).

All fifteen runs reached victory or defeat. The single gun loses at swarm 7; omitting mortars loses at swarm 20. Standard mixed defenses reach swarms 24–25, with wins and losses depending on map and composition. Relaxed wins all three established seeds. Veteran loses at swarms 5, 21 and 23. This pilot differs from the 0.18 pilot: its recovery rule abandons uncovered structures, including exposed wall sections, after a prolonged fight, so campaign outcomes are not an isolated performance A/B comparison.

The ordinary defense plans four sentries, twelve gun turrets and four mortars. The pulse variant replaces four inner guns with pulse turrets. The no-artillery variant omits the four mortars. The single-gun control retains production but uses just one gun emplacement. Results apply to this particular scripted builder; human difficulty still requires tester feedback.

The old pulse turret had mortar-like sustained damage with shorter range, a smaller blast and higher power consumption. Pulse now deals 1.1× gun damage every 1.05× gun interval, with radius 1.6 and range three tiles below the gun. Mortars retain radius 2.25 and range two tiles above the gun. Pulse has approximately twice the mortar's sustained direct damage, but costs more power, has shorter reach and uses more ammunition per second. Eight bursts still consume one gear. A level-30 pulse hits for 126.5; a standard final-swarm runner has 398 HP, so it does not one-shot final enemies.

Drill and smelter speed gains remain +25% of base per upgrade, with one refined plate per ore. Shared storage limits, thirty turret levels, swarm unlock gates and late component costs are retained.

## Regression checks

- Floating-point framebuffer reads for 80 creatures at zoom 14 and 44, 160 creatures at zoom 14, and 420 creatures at zoom 44: no non-finite values.
- First repeated workshops and first lamps use pipelines drawn during loading. A readback drains queued GPU work before the loader closes. Placement checks compare completed frames against a shadow-updating baseline, rather than treating fast CPU submission as completed rasterization. Eight full point lights remain available at normal graphics quality. Lamp fittings use eleven meshes instead of twenty-three while retaining all 1,524 triangles, materials and independently switchable bulbs.
- Mesh integrity/packing boundaries, original targeting order, cache invalidation, sawmill felling, instance movement/removal, selection proxies and dynamic shadow transitions have automated coverage.
- Full simulation/interface suite: 188 passing tests.

The completed-frame placement baseline took 2127 ms in the local software renderer with shadows forced to update; first lamp placement took 2000 ms and eight lamps took 1885 ms. The two-workshop placement took 2169 ms against a 2543 ms empty-placement baseline. Normal graphics retains eight real point lights and every lamp halo. These comparisons show no extra cold-placement pause; they do not claim playable hardware FPS from a CPU software renderer.

The machine-readable report records placement measurements and render errors. Native Windows checks and screenshots are generated from the actual packaged game by `scripts/build-windows.ps1`.

## Reproduce

```sh
npm ci
npm test
npm run build
node scripts/play-campaign-matrix.mjs
# Use CAMPAIGN_WORKERS=4 on a machine with spare CPU capacity. Default: 2.
CHROME_BIN=/usr/bin/chromium npm run test:render
CHROME_BIN=/usr/bin/chromium node scripts/benchmark-renderer.mjs work/renderer-candidate
CHROME_BIN=/usr/bin/chromium BENCH_BASELINE=1 node scripts/benchmark-renderer.mjs work/renderer-baseline
node --expose-gc scripts/benchmark-assets.mjs work/assets.json
node scripts/benchmark-simulation.mjs work/simulation.json
# Reference simulation (all shared dependencies from the original tag):
mkdir -p work/reference-v018
git archive v0.18.0 public/shared | tar -x -C work/reference-v018
SIM_MODULE="$PWD/work/reference-v018/public/shared/sim.js" node scripts/benchmark-simulation.mjs work/simulation-baseline.json
```

The baseline renderer command requires the `v0.18.0` git tag. `SIM_MODULE` can select a reference simulation file for CPU/campaign comparisons; its relative shared-module imports must resolve from that file's location. Raw logs, synthetic captures and campaign saves are written to ignored `work/`. Windows packaging: `./scripts/build-windows.ps1`.
